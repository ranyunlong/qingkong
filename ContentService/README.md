# 小晴空公共内容后台

Python 3.10+，使用标准库 HTTP server、SQLite、音频元数据依赖 `mutagen` 与图片处理依赖 `Pillow==13.0.0`。只管理所有读者可见的文章、配图、专辑与音轨目录。没有用户账户、个人健康／心情／日记接口，不上传或托管音频，不发起医学查询或调用云端 AI。管理员主动识别音乐链接时，服务会临时下载文件，读取标签并计算完整文件摘要，处理后删除临时文件；文章配图可上传本地图片或使用长期 HTTPS 图片链接。

## 本地启动

以下命令从项目根目录运行。程序默认监听 `127.0.0.1`，默认端口 `8787`；容器可显式指定 `--host 0.0.0.0`。后端已于 2026-11-22 部署至 `https://xqk.geckoai.cn`；专业内容审核、正式音轨授权和配对设备验收仍待完成。

已有服务器及 HTTPS 入口时，使用根目录 `compose.yaml`；域名 `xqk.geckoai.cn` 的镜像拉取、凭据生成与反向代理步骤见 [Docker 部署说明](DEPLOYMENT.md)。当前服务部署在 `/opt/qingkong-content`，管理入口为 `/admin/login`，首次内容库为空。

1. 使用 Python 3.10 或更新版本创建本地环境并安装依赖：

   ```sh
   python3 -m venv .venv
   . .venv/bin/activate
   python -m pip install -r ContentService/requirements.txt
   ```

2. 生成管理员密码散列（交互输入，至少 12 字符；密码不进入命令历史）：

   ```sh
   python3 -m ContentService.server --hash-password
   ```

3. 通过本机私密环境设置 `QINGKONG_ADMIN_USERNAME`、`QINGKONG_ADMIN_PASSWORD_HASH`（上一步完整结果）及 `QINGKONG_SESSION_SECRET`（至少 32 字符随机秘密）。没有默认管理员、默认密码或内置生产秘密。环境文件不得提交。可用以下命令生成会话秘密，并通过自己的安全方式设置环境变量：

   ```sh
   python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```

4. 设定本机文件权限并启动：

   ```sh
   umask 077
   python3 -m ContentService.server --db ContentService/content.sqlite3 --seed-drafts
   ```

5. 浏览器打开 `http://127.0.0.1:8787/admin/login`。文章管理在 `/admin/articles`，音乐管理在 `/admin/music`；`/admin` 保留为文章入口。公共快照在 `/api/v1/snapshot`。未发布任何内容时正常返回空数组。iPhone 与 Watch 默认连接 `https://xqk.geckoai.cn`，没有用户可见的服务地址设置。

`--seed-drafts` 幂等添加 18 个编辑选题与提纲，全部标为「未经专业审核」，无参考来源、无审核信息、无已发布副本；它们不构成医学内容，也不会出现在公共接口。首批正式文章仍需人工撰写、核实来源、实际专业审核后逐篇明确发布。

[首批待审包](EDITORIAL.md)另提供与这 18 个选题对应的完整中文正文、机构来源及审核清单，数据为 `editorial-drafts.json`。全部仍为未审核草稿，不会随启动命令导入；须按说明人工整理并完成实际专业审核。该包不构成已发布的首批专业内容。

## 编辑操作

- 文章与音乐分区管理，音乐按专辑展示歌曲；支持创建、草稿编辑和安全预览。内容保存及状态操作记录操作者、UTC 时间及历史版本。
- 文章正文支持标题、粗体、斜体、下划线、删除线、列表、引用、HTTPS 链接和图片。编辑器支持本地图片上传、填写图片链接、粘贴 HTTPS 图片地址或剪贴板中的本地图片。服务端按标签白名单清洗可选 `bodyHTML`，去除脚本、事件及样式，图片只保留合法 HTTPS 地址、替代文字及可选尺寸；每篇最多 30 张图片。HTML 最多 120000 字符，派生的 `body` 纯文本最多 60000 字符；纯文本保留图片替代文字，未填写时使用「正文图片」。旧文章与仅提交 `body` 的接口继续兼容。手机使用原生控件按正文顺序显示文字与图片，图片下载受限，不使用 WebView。参考来源在页面逐条添加、移除和编辑标题／链接，API 仍使用 `references:[{title,url}]`。
- 图片上传仅接受静态 JPEG、PNG、WebP，原始文件最多 10 MiB，像素总数最多 2000 万且单边最多 10000。服务端重新编码、去除 metadata，必要时缩至最长边 2560，并继续缩图直至输出不超过 8 MiB，保存为数据库同级 `uploads/` 下的 JPEG 或 PNG；Docker 中随数据卷持久化。同一时间只处理一张上传图片，Linux 图片处理子进程内存上限为 384 MiB。上传必须登录并通过 CSRF 与同源 Origin 校验。上传不会修改公共 revision、保存文章或自动发布，但文件上传完成后即可通过难以猜测的摘要 URL 公开读取；该功能仅用于面向所有读者的公共文章配图，不用于私人图片。数据备份和恢复应同时包含数据库与 `uploads/`。
- 服务端保存文章本身不会请求外部图片；浏览器编辑／预览及手机展示图片时会向图片地址发起 GET。外部图片的可访问性、授权及提供方隐私规则仍由运营者确认，本地上传的配图由本服务公开提供。
- 文章：保存草稿 → 补齐真实来源 → 提交审核 → 填写实际审核人、资质及范围，明确确认审核 → 明确发布。系统只记录管理员的审核声明，不能代替真实专业审核。
- 已发布内容再编辑仅产生新草稿，旧公共版本继续可见。文章重新编辑会清空审核信息，须再次审核。新版本明确发布后才替换公共内容。
- 历史恢复只生成草稿，不自动恢复上线与审核。撤回立即移除公共版本并产生墓碑；再次发布会清除对应墓碑。撤回专辑同时撤回所属已发布音轨，再上架专辑不会自动重上架曲目。
- 新建歌曲先选择所属专辑，再粘贴长期 HTTPS 音频地址；页面自动读取文件，也可点击「读取文件信息」重试。识别会填入文件内标题（无标签时使用 URL 文件名）、摘要、时长、真实字节数、完整 SHA256、`sha256-` 加摘要前 12 位的文件版本，以及文件内已有的版权标记；填入后可手动修改。没有摘要或版权标签时保持空值，版权截止时间不会自动推断。失败时显示原因，仍可依据实际文件手动填写。
- 文件识别接口 `POST /admin/api/media/inspect` 仅在登录与 CSRF／Origin 校验通过后请求媒体，不创建草稿、不写数据库、不自动发布。下载上限 200 MiB，下载及解析共用约 60 秒期限，最多同时处理两个请求；最多跟随三次 HTTPS 重定向，每次重新验证全部 DNS 地址为公网，连接固定到验证过的 IP 并按原域名校验证书。不会继承代理环境。
- 音轨记录稳定 UUID、所属专辑、长期 HTTPS 地址、真实文件时长／字节数／SHA256、文件版本及版权信息。改动媒体地址、字节数或摘要必须改文件版本；先发布专辑再发布音轨。识别只能读取文件中的声明，不能验证版权、授权真实性或授权范围，运营方仍需核实并补齐资料。客户端据字节数与 SHA256 检查完整下载。
- 授权期限为 UTC ISO8601 或空（运营者确认无限期）。到期音轨在下一次公共读取／管理状态操作时自动撤回并持久记录墓碑。曲目顺序由各音轨 `sortOrder` 决定；专辑 `trackIDs` 由已发布曲目计算。
- 链接只接受 HTTPS，拒绝凭据、临时签名、已知令牌参数及内网 IP。无法从 URL 证明域名长期可访问，运营者仍须确认 OSS 的公开长期访问策略、真实版权、播放稳定和循环接缝。

## 登录与运行边界

密码使用随机盐 PBKDF2-HMAC-SHA256（600000 次），验证采用常量时间摘要比较。登录前后都要求 CSRF token；登录成功轮换随机会话，Cookie 为 `HttpOnly; SameSite=Strict`，本机 HTTP 默认不设置 `Secure` 以保持可用。管理写请求还校验存在的 `Origin`。按来源地址限制 15 分钟内最多 5 次失败登录，会话最长 8 小时，登出立即失效，重启使所有会话失效。

页面使用 `Referrer-Policy: same-origin`，保留同源 HTML 表单的 Origin，不向外站发送 Referer；`no-referrer` 会令原生表单 POST 的 Origin 变成 `null`，与严格来源校验冲突。更新服务后需重新打开登录页，旧页面的会话与表单令牌不再有效。

仅为用户明确要求的功能验收，标题以 `[测试]`、正文以 `【仅供功能测试】` 开头的非医学文案可选择「发布功能测试（未专业审核）」。这会生成 `testOnly:true` 与独立操作历史，客户端明确显示测试状态，不填写虚假的专业审核人或资质。正式文章继续使用逐篇审核流程；测试音轨的版权字段如实标注用户提供及正式资料待补充。

`QINGKONG_SECURE_COOKIES=1` 仅适用于经 HTTPS 反向代理访问本机服务的环境；同时以 HTTPS Origin 校验。Python 内置 HTTP server 不直接面向公网。Docker 配置提供单实例后端、持久化数据、健康检查和运行日志轮转，接入现有 HTTPS 反向代理；管理访问限制、备份、监控及代理／OSS 日志保留按实际服务器配置，并更新隐私披露。开源派生项目可修改客户端默认 HTTPS 根地址，不使用服务器回环 HTTP 地址。

程序不记录客户端 IP、URL 查询、请求内容、凭据或健康数据；SQLite 记录内容、发布历史、审核声明和管理员名称，会话及登录限流仅在内存。SQLite 仅支持此单进程实例的写协调；运行多个独立进程不在当前支持范围。备份时先停止服务，再一起保存数据库与同级 `uploads/` 目录；恢复后应从同一备份恢复全部公共内容和配图，客户端若发现 revision 回退应要求完整重同步。

## 验证

```sh
python3 -m unittest discover -s ContentService/tests -v
```

测试用临时数据库与临时本机 HTTP 端口，覆盖匿名访问、草稿隔离、登录限流、CSRF／Origin、审核前置条件、修订、撤回与墓碑、历史恢复、专辑连带下架、版权到期、文件版本、链接／输入校验、富文本清洗和参考来源列表。音乐识别使用本地合成音频验证标签、时长与真实文件摘要，以模拟网络验证公网地址、重定向、固定 IP、大小及时间限制；接口测试验证认证通过前不调用识别、错误响应及识别不写库。需要执行环境允许回环端口监听；不会访问外网音频或调用付费服务。

公共／管理 JSON 详见 [API.md](API.md)。
